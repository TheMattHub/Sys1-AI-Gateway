# Distillation notes

## TEST2 (frozen 2026-10-20)
Written by a fresh subagent (Claude Sonnet 5.5) that saw only the 90 tool names, never the descriptions or any
existing query. 100 rows, all 90 tools gold at least once. Its own interpretation doubts, kept as it gave them:
- study_view = the study's main picture; study_show = the live control room.
- study_page_html = one standalone web page of the outcomes; study_package = bundle the study files for hand-off.
- study_extensions = optional add-on analyses (cost, energy).
- get_model_format = the JSON model format spec; write_model = store a hand-written full model JSON.
- list_records / get_record_schema = generic data records (shifts, products, maintenance).
- evaluate_policy = compare dispatch/decision policies; fit_surrogate = a fast approximation of the model.
- set_initial_state = start the run from current work in progress.
- Twin: get_plant_timeline = history of plant events; get_twin_monitor = live state.
Doubts found later are logged below; the file itself is never edited.

## TRAIN2 (2026-10-20)
1,080 requests generated by three Claude Sonnet 5.5 subagents (30 tools each, 12 per tool) from the full tool
descriptions and the 54 TRAIN queries; none saw TEST, TEST2 or HELD_OUT_2. prep.py (word-set Jaccard >= 0.6)
dropped 6 near-duplicates and 7 near-copies of TEST2/HELD_OUT_2 rows: 1,067 kept, 106 held out (seed 0).

## TEST3 (frozen 2026-10-21)
150 requests by four writers (`write3.py`), each seeing only the 90 tool names and the target tool, one prompt
for all, asked length rotating short / one sentence / two or three sentences: Claude Opus 5.5 (API) 38, Gemma 4
E4B (Ollama, temperature 0.8) 40, Qwen3-1.7B (the AnyJev base on disk, 4-bit NF4, temperature 0.8, no thinking) 34,
LiquidAI d1-3B (llama-server /v1/chat/completions, temperature 0.8) 38. d1-3B writes plain text fine, so it stayed.
Targets: seeded shuffle of the 90 plus 70 more (seed 3), 40 slots per writer. Sanity pass: 10 drops, all Qwen3
short answers under 3 words ("Order nodes.", "Add block"), retried up to 3 times (one remove_node slot never
passed); no answer named a tool verbatim. Dedupe (Jaccard >= 0.6): 9 drops (3 near TRAIN2, 1 near TEST2, 5 near an
earlier TEST3 row). Every drop: `test3_drops.jsonl`; raw answers: `test3_raw/`. 89 of 90 tools are gold:
study_revert's only row ("Undo the last change.", d1-3B) was a near-copy of a TRAIN2 row.
Doubts, written before any picker saw the set (the file is never edited; row = 0-based line):
- The writer's request does not fit its target (the gold is the target anyway): 3 upsert_scenario "Save my plan
  for tomorrow", 29 remove_segment "Fix the segment", 40 list_continuous "Move to next step", 52 list_block_types
  "Close the model", 84 run_reality_checks "Bring the model to life", 95 remove_record "Fix the record", 107
  remove_segment "Moving some parts of the system", 110 redo "Undo that last configuration change", 140 write_model
  "Add blocks to the model", 144 find_tool "update the calendar and resources", 92 study_package "Upload my new
  project package", 14 import_mdl "Upload my Excel model file". Ten of the twelve are Qwen3-1.7B or d1-3B rows.
- Closer to a sibling tool: 5 describe_block_type and 59 describe_distribution ask what is available (list_*),
  12 write_model asks to save (save_model), 129 upsert_segment asks for a production step (add_block).
So small writers add label noise; the per-writer table shows how much. Opus rows look clean.
